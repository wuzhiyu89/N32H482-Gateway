## 三、平台必须满足的 4 个硬条件

1. **直链、不跳转**。ML307R 的 `AT+MHTTPCREATE="https://host"` 是**绑定单个 host** 的，
   跨域 302（GitHub Release、Gitee raw）会打断这条连接。→ 首选 `kappa.lol` / `uguu.se` / OSS 直链。
2. **`Content-Length` 必须准确**，且等于下发 `ota.start` 里的 `size`。
3. **支持 `Range`**（断点续传要用）。上面两家实测都返回 `206 + Content-Range`。
4. **可算出 MD5**：本地 `Get-FileHash -Algorithm MD5`，或直接用 kappa 返回的 `checksum`。
   下载回来后必须逐字节一致 —— 已实测两家都能做到：

```
kappa: size=65536 md5=9E96D33CF71A79CAABD00B319E115AF5 match=True
uguu : size=65536 md5=9E96D33CF71A79CAABD00B319E115AF5 match=True
```

## 四、上传 / 校验命令（PowerShell + curl）

```powershell
# 上传到 kappa.lol（返回 JSON，含 md5 checksum 与直链）
curl.exe -F "file=@fw.bin" https://kappa.lol/api/upload

# 上传到 uguu.se（返回纯文本直链，3 小时过期）
curl.exe -F "files[]=@fw.bin" "https://uguu.se/upload?output=text"

# 本地 MD5 + 大小（下发 ota.start 用）
Get-FileHash fw.bin -Algorithm MD5
(Get-Item fw.bin).Length

# 模拟设备端"分段拉取 + 校验"
curl.exe -r 0-1023 -o part0.bin https://kappa.lol/xxxx
```

## 五、下发报文长这样

> ⚠️ **2026-10-05 更正**：原来这里把四个参数写成**顶层字段**，那样网关会回 **1001**。
> 信封约定是 `{"cmd","msgId","ts","auth","data":{...}}`，`ota.start` 的四个参数
> **必须放在 `data` 里面**（`cloud_proto.c` 的 `out->data = cj_get_sub(json, "data")`
> 之后才读 `size`/`version`/`url`/`md5`）——顶层写法的现象就是 `req->data == NULL`
> 直接 1001，连 URL 都不校验，很容易误判成"MD5 错了"。

```json
{"cmd":"ota.start","msgId":"o-01","ts":1791136499,"auth":"",
 "data":{"version":"1.2.1",
         "url":"https://kappa.lol/wRqcN6",
         "md5":"9e96d33cf71a79caabd00b319e115af5",
         "size":65536}}
```

## 六、模块侧 HTTP 客户端（✅ **已确认支持，含 HTTPS**）

> **本节已结案**：后续台架 `AT+MHTTPCFG=?` 返回了完整参数表（含 `"ssl"`），
> 并找到了中移原厂《HTTP_HTTPS 用户手册 V4.0.0》佐证。
> **完整命令表 / URC / 错误码 / 下载架构设计 → 见 [OTA_HTTP_设计_v1.md](../OTA_HTTP_设计_v1.md)**

### 6.1 台架实测（首轮，曾被误判为"不支持"）

```
#at AT+MHTTPCFG=?
[G4_RX] +MATREADY          ← 模组 AT 应用层重启（工程里已累计 15 次）
[G4_RX] OK

#at AT+MHTTPCREATE=?
[G4_RX] OK                 ← 只有一个裸 OK，没有 +MHTTPCREATE: (...) 参数表
```

**两条都不能当结论**：

- `AT+MHTTPCFG=?` 的 `+MATREADY` 距发送只有 9 ms，说明**模组本来就在重启途中**，
  这条应答是半开机状态吐的，不可信。
- `AT+MHTTPCREATE=?` 只有裸 `OK`。但"`=?` 测试式拿不到参数表"≠"命令不存在"——
  中移这族 AT 的 `=?` 本来就可能没实现。

### 6.2 旁证：MHTTP 这一族**是存在的**

社区帖（2024-05，[whycan t_10975](https://whycan.com/viewtopic.php?id=10975)）里用户明确说
"中移 ML307R/A 原厂模块（AT 固件）确实可以做 HTTP POST"，并贴了原厂《HTTP 用户手册》的用法：

```
AT+MHTTPCREATE="http://host:80"
AT+MHTTPCONTENT=0,0,0,"{...}"
AT+MHTTPREQUEST=0,2,0,"/post"     // 1=GET, 2=POST
```

他失败的原因是 404（路径错），**不是命令不支持**。

但注意：**本工程手上的 `ML307R_ATCommands.pdf` 是节选**——29 页，只覆盖到
`MIPOPEN/MIPSEND/MIPRD`（TCP/UDP socket），连工程正在用的 `AT+MQTTCONN` 都没写进去。
所以"手册里没有 MHTTP"完全不能作为反证。**原厂《HTTP_HTTPS 用户手册 V4.0.0》已找到并归档**（见本节开头）。

### 6.3 真身验证结果

```powershell
# 第 1 步：纯 HTTP 冒烟（baidu 一定通，先确认命令族活着）
#at AT+MHTTPCREATE="http://www.baidu.com"
#at AT+MHTTPREQUEST=0,1,0,"/"          ← 看有没有 +MHTTPNMI/正文 URC 吐出来
#at AT+MHTTPDEL=0

# 第 2 步：TLS 冒烟（决定平台选型）
#at AT+MHTTPCREATE="https://kappa.lol"
#at AT+MHTTPCFG="ssl",0,1,1
#at AT+MHTTPREQUEST=0,1,0,"/wRqcN6"    ← 期望 Content-Length: 65536
#at AT+MHTTPDEL=0
```

用 `kappa.lol/wRqcN6` 当靶子的好处：它是**已知 65536 字节、MD5 `9e96d33cf71a79caabd00b319e115af5`** 的
确定载荷，模块拿到多少字节、MD5 对不对，一眼可判。

### 6.4 退路：`AT+MIPOPEN` 手写 HTTP/1.1

若 MHTTP 确实不可用，退回 `AT+MIPOPEN=0,"TCP","<host>",80` + `AT+MIPSEND` 手发
`GET /path HTTP/1.1\r\nHost: ...\r\nRange: bytes=a-b\r\n\r\n`。手册 6.3 节有现成例子。
**但这条路只有明文 HTTP**——所以平台必须选 80 端口直出的（OSS/COS/自建）。
工程目前 `broker.emqx.io:1883`（明文），没有任何 TLS 使用经验可复用。
