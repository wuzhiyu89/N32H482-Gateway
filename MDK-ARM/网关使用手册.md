# 网关使用手册（云端对接）

> 适用设备：N32H482RE 4G + LoRa 网关
> 适用固件：1.0.x（A/B 双分区版本）
> 文档定位：**仅面向云平台对接**。包含连接方式、上下行报文格式、数据口径、配置项、绑定/解绑、联动控制与 OTA。
> 不包含现场安装、硬件接口、内部实现与本地维护手段。

---

## 1. 网关角色

网关是**自治边缘节点**：

- 通过 4G 连接 MQTT 服务器，与云平台交换 JSON 报文；
- 通过 LoRa 管理水位传感器与联动设备（声光报警器 / LED 屏 / 一体机，最多各 5 台）；
- 水位分级、档位判定与联动动作**在网关本地完成**，断网也继续运行；
- 云平台负责：配置下发、手动控制、数据展示与 OTA 升级。

平台需要保存两类标识：

| 标识 | 说明 |
|---|---|
| `gwId` | 网关唯一标识，26 位十六进制大写（13 字节），首字节 `11`；同时用于 MQTT 主题与 ClientID |
| 子设备 `uid` | 26 位十六进制大写（13 字节），首字节 `21`=液位传感器 / `31`=声光、LED、一体机；绑定成功后由网关分配并在 `event.device(bound)` 中给出 |

> `uid` 请平台视为**不透明字符串**保存，不要自行拼接或解析。

## 2. 连接与主题

### 2.1 MQTT 连接

| 项 | 说明 |
|---|---|
| 地址/端口 | 由 `network.host` / `network.port` 配置，默认 1883 |
| TLS | 当前固件仅支持明文 MQTT（`network.tls = false`） |
| ClientID | 固定等于 `gwId` |
| 用户名/密码 | `network.username` / `network.password`，由现场配置 |
| KeepAlive | `network.keepAliveSeconds`，默认 60s（30~300） |
| 遗嘱 LWT | 独立主题 `rt/gw/{gwId}/lwt`，retained，内容 `{"online":false}` |

主题前缀统一为 `rt/gw/{gwId}/`。

### 2.2 主题表

| 主题 | 方向 | QoS | Retained | 用途 |
|---|---|---|---|---|
| `rt/gw/{gwId}/cmd` | 平台 → 网关 | 1 | 否 | 下行命令 |
| `rt/gw/{gwId}/cmdresp` | 网关 → 平台 | 1 | 否 | 命令应答 |
| `rt/gw/{gwId}/telemetry` | 网关 → 平台 | 0 | 否 | 水位遥测 |
| `rt/gw/{gwId}/event` | 网关 → 平台 | 1 | 否 | 事件 |
| `rt/gw/{gwId}/status` | 网关 → 平台 | 1 | **是** | 在线状态/心跳 |
| `rt/gw/{gwId}/lwt` | 网关 → 平台 | 1 | **是** | 掉线遗嘱 |

平台应同时订阅 `status` 与 `lwt`：`status` 的 retained 只由网关主动上报维护，`lwt` 由 broker 在网关掉线时代发。

> 遥测当前以 QoS 0 发布（平台按 QoS 1 订阅也能收到，弱网下可能丢包，见第 12 章差异说明）。

## 3. 报文信封

### 3.1 下行命令

```json
{ "cmd": "cfg.set", "msgId": "a1b2c3d4", "ts": 1735689600, "auth": "", "data": { } }
```

### 3.2 命令应答

```json
{ "cmd": "cfg.set", "msgId": "a1b2c3d4", "code": 0, "msg": "ok", "ts": 1735689601, "data": { } }
```

### 3.3 上行事件/遥测

```json
{ "event": "telemetry.report", "msgId": "m001", "ts": 1735689600, "data": { } }
```

### 3.4 通用约定

- **编码**：UTF-8 JSON；下行 JSON 上限约 **6 KB**（超限网关不处理、不应答）。
- **`msgId`**：平台生成，≤16 字节；应答原样带回。网关记住最近 **4 条**、**60 秒**内的 `msgId`：同 `msgId` 重发不会重复执行，而是重放上次应答。平台超时重发请**更换新 `msgId`**。
- **`ts`**：Unix 秒。上行事件带**事件发生时刻**的原始时间戳（补报不改）。网关时间来自 4G 模组网络授时；授时完成前的报文时间可能不准，平台可用接收时间兜底。
- **`auth`**：若 `system.password` 非空，下行必须携带该密码，否则返回 `1008`；为空则不需要。
- **应答较大**：模组单条发布上限约 1024 字节，超过时网关返回 `1011`（`response too large; query by section`）。`cfg.query` 请按域查询。
- 命令执行结果以 `cmdresp` 为准；设备侧动作的最终结果另经 `event.action` 异步上报。

### 4.1 系统类

**`sys.query_status`**（无参数）

响应 `data`：

```json
{ "fwVersion": "1.0.0", "slot": "A", "configVersion": 6, "rsrp": -85,
  "uptimeSeconds": 3600, "mode": "auto", "currentGear": 2,
  "sensorsOnline": 2, "sensorsTotal": 2, "devicesOnline": 1, "devicesTotal": 1,
  "bufferedEvents": 0 }
```

`bufferedEvents` 为尚未补报的缓存事件条数；`slot` 见第 10 章 OTA。

**`sys.reboot`**：参数 `delaySeconds`（默认 0）。应答 `code 0` 后延迟重启。

**`sys.factory_reset`**：参数 `keepNetwork`（bool，默认 true）。恢复后 `sensors[]`/`devices[]` 清空、`configVersion` 归零；`keepNetwork=false` 时网络配置也回出厂。

**`sys.time_sync`**：已废弃。网关时钟由 4G 模组自动授时，平台不应再下发；固件保留兼容应答。

### 4.2 配置类

**`cfg.set`**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `expectVersion` | uint32 | 是 | 与当前 `configVersion` 不一致返回 `1002`，`data.currentVersion` 给出当前值 |
| `sections` | object | 是 | 要修改的配置域；值为该域的完整或部分字段 |

- `sensors[]` / `devices[]` 按 `uid`、`gears[]` 按 `gear` 逐条合并；未出现的条目不变。
- **删除设备只能通过 `sen.unbind` / `dev.unbind`**，不要用 `cfg.set` 表达删除。
- 应答：`{"configVersion": N, "applied": ["thresholds","sensors"], "rejected": []}`；整域校验失败只给域名，不给原因。
- `network` 域与 `system.gwId` 修改后**重启生效**；生效前旧连接保持。
- `network.password` 若原样回传 `"*****"`，视为“不修改”。

**`cfg.query`**

参数 `sections`（字符串数组，缺省 `["all"]`）。响应为完整配置结构（含 `meta`）。

- `network.password` 固定掩码为 `"*****"`；
- 全量应答可能超过 1024 字节而返回 `1011`，请按域查询并在平台本地组装。

### 4.3 传感器

**`sen.bind`**：参数 `name`（可选）、`pairWindowSeconds`（默认 60，1~300）。
响应 `{"pairWindowSeconds":60}` **仅表示窗口已打开**；结果经 `event.device` 异步上报：
`bound`（附 `uid`）/ `bind_failed`。**一个窗口只能绑定一台设备**，绑 N 台需开 N 次窗口。

**`sen.unbind`**：参数 `uid`。`code 0` 仅表示受理；结果经 `event.device`：
`unbound`（已删除）/ `unbind_failed`（保留原绑定）。

**`sen.set`**：参数 `uid` + `sensors[]` 可写字段（见第 8 章）。
- 不得携带只读字段；携带返回 `1001`；
- `code 0` 表示**配置已保存**。涉及上报周期等设备侧参数时，网关在设备下次上报窗口经 LoRa 下发，不等待设备确认；
- 目标 UID 未绑定返回 `1003`。

**`sen.query`**（无参数）：`data.sensors[]`，每项为 `sensors[]` 全字段 + `online` / `lastLevelCm` / `batteryPercent` / `lastTs`。从未上报过的设备也会返回，`online=false` 且不带历史字段。

### 4.4 联动设备

**`dev.bind`**：参数 `name`（可选）、`pairWindowSeconds`、**`type`（必填：1 声光 / 2 LED / 3 一体机）**。窗口与结果语义同 `sen.bind`。

**`dev.unbind`**：同 `sen.unbind`。

**`dev.set`**：参数 `uid` + `devices[]` 可写字段。`serial`、`type` 为只读，携带返回 `1001`。

**`dev.ctrl`**（手动控制）

| 参数 | 必填 | 说明 |
|---|---|---|
| `uid` | 是 | 目标设备 `uid`，或 `"all"` |
| `gear` | 是 | 档位 0~3 |
| `ledText1` | 否 | 第一半屏文本（横屏=上，竖屏=左） |
| `ledText2` | 否 | 第二半屏文本 |
| `ttsText` | 否 | 语音文本 |

- **文本原样下发**：给了（含空串）就用给的；**没给就是空**，网关不会用档位模板自动补文案。
- 文本中的 `{level}` 会被当前水位替换（整数 cm，截断；一位数补一个尾随空格）。
- 执行后网关进入 `manual` 模式，`manualTimeoutSeconds` 到期自动回 `auto`。
- 应答：

```json
{ "code": 0, "data": { "results": [ {"uid": "31...", "code": 0} ] } }
```

`results[].code`：`0`=已投递到下发队列；`1003`=目标不存在/已停用；`1007`=内部错误。
真正的空口执行结果经 `event.action` 异步上报，网关后台重试。

**`dev.query`**（无参数）：`data.devices[]`，每项为 `devices[]` 全字段 + `online` / `batteryPercent` / `lastTs`。

### 4.5 档位与模式

**`rule.set`**：只允许 `gears` 域（数组，按 `gear` 合并），携带其他域返回 `1001`；应答 `code 0` + `configVersion`。

**`rule.query`**（无参数）：`data.gears[]` + `data.rules{}`。

**`rule.mode`**：参数 `mode`（`auto`/`manual`）、`manualTimeoutSeconds`（可选）。切回 `auto` 时网关立即按当前水位重评估一次。

### 4.6 OTA

**`ota.start`**

| 参数 | 必填 | 说明 |
|---|---|---|
| `version` | 是 | 目标版本 |
| `url` | 是 | 固件 HTTP 地址（≤255 字节） |
| `size` | 是 | 固件字节数（不超过单槽 208 KB） |
| `md5` | 是 | 固件 MD5（32 位小写 hex） |

返回：`0` 受理；`2001` URL 非法；`1006` 版本相同或已有升级在途；`1010` 空间不足。

**`ota.query`**：`{"state":"downloading","percent":42,"targetVersion":"1.0.1"}`。
`state`：`idle` / `downloading` / `verifying` / `installing` / `failed`（**无 `done`**）。

**`ota.abort`**：仅 `downloading` 可中止，否则 `1006`。

> 升级是否成功，以重启后 `status.report.fwVersion` 变为新版本为准。

## 5. 上行报文

### 5.1 `status.report`（status 主题，retained）

周期 = `network.statusIntervalSeconds`（10~600，默认 30s）。

```json
{ "event": "status.report", "msgId": "h001", "ts": 1735689600,
  "data": { "online": true, "fwVersion": "1.0.0", "slot": "A", "configVersion": 7,
            "rsrp": -85, "uptimeSeconds": 3600, "mode": "auto", "currentGear": 2,
            "sensorsOnline": 2, "sensorsTotal": 2,
            "devicesOnline": 1, "devicesTotal": 1 } }
```

字段说明：

| 字段 | 说明 |
|---|---|
| `rsrp` | 4G 信号强度换算值，dBm，负值；`0` 或正数表示采集失败，平台按“未知”展示 |
| `uptimeSeconds` | 本次上电运行秒数，重启归零 |
| `configVersion` | 配置版本号，`cfg.set` 实际变更时 +1 |
| `slot` | 当前运行分区 `A`/`B`（OTA 选包用，见第 10 章） |
| `sensorsOnline/Total` | 已绑定并在线的传感器数 / 总数 |
| `devicesOnline/Total` | 已绑定并在线的联动设备数 / 总数 |

### 5.2 `telemetry.report`（telemetry 主题）

**触发周期与心跳严格一致**：同一个 `network.statusIntervalSeconds`；上电后第一条立即发送，之后每个周期一条。不因水位变化额外触发。

```json
{ "event": "telemetry.report", "msgId": "m001", "ts": 1735689600,
  "data": {
    "sensors": [
      { "uid": "21...", "levelCm": 12.3, "rawMm": 123,
        "batteryPercent": 80, "rssi": -87, "ts": 1735689598 }
    ],
    "effective": { "levelCm": 12.3, "status": "Alarm", "gear": 3 }
  } }
```

- 每条遥测是**全量快照**：当时所有“在线且 enabled”的传感器一起上报；一台有效的都没有时本条不发。
- `sensors[]` 每台带**自己的 `ts`**（网关收到该帧的时间），各路采样不一定同时。
- `levelCm` = 传感器上报值（mm）/10，保留一位小数；`rawMm` 为原始 mm。
- `batteryPercent` 为百分比；`rssi` 为该帧 LoRa 信号强度。

**有效水位（双口径）**：

| 用途 | 口径 |
|---|---|
| `effective.levelCm` | 参与计算的在线传感器**平均值** |
| `effective.status` / `effective.gear` | 按在线传感器**最高值**判定 |

两者可能不一致（例如两路 5cm/20cm：`levelCm≈12.5`，`status=Alarm`、`gear=3`）。平台展示趋势可用 `levelCm`，告警状态以 `status`/`gear` 为准。

`status` 取值：`Normal`（一直正常）/ `Warning` / `Alarm` / `Resolved`（此前有积水、现已退去）。

### 5.3 `event.status_change`

```json
{ "event": "event.status_change", "msgId": "s001", "ts": 1735689600,
  "data": { "from": "Normal", "to": "Warning", "gear": 2, "levelCm": 8.1 } }
```

受 `thresholds` 的 `minChangeCm`、`eventMinIntervalSeconds`、`confirmCount` 约束。

### 5.4 `event.action`（联动执行结果）

```json
{ "event": "event.action", "msgId": "a001", "ts": 1735689600,
  "data": { "gear": 2, "trigger": "auto",
            "results": [ {"uid": "31...", "code": 0} ] } }
```

`trigger`：`auto`（阈值触发）/ `manual`（平台手动）/ `failsafe`（传感器全部失联时的兜底）。

### 5.5 `event.device`

```json
{ "event": "event.device", "msgId": "v001", "ts": 1735689600,
  "data": { "uid": "21...", "devType": "sensor", "event": "offline" } }
```

`event` 取值：`bound` / `bind_failed` / `unbound` / `unbind_failed` / `online` / `offline` / `low_voltage`。
`bound` 时附带网关分配的 `uid`，平台必须保存；如有 `serial` 字段则一并返回。

### 5.6 `event.buffered`（断线补报）

```json
{ "event": "event.buffered", "msgId": "b001", "ts": 1735693200,
  "data": { "events": [ { "event": "event.status_change", "msgId": "s099",
                          "ts": 1735690000, "data": { } } ] } }
```

- 每条内层事件保留**原始 `ts` 与 `msgId`**；
- 单条最多 **16** 个事件，超出分多条发送。

### 5.7 `ota.progress`

```json
{ "event": "ota.progress", "msgId": "p001", "ts": 1735689600,
  "data": { "state": "downloading", "percent": 42, "targetVersion": "1.0.1" } }
```

- `state`：`downloading` / `verifying` / `installing` / `failed`；
- 下载完成会单独发一条 **`verifying, percent=100`**，随后是 `installing, 100`；
- `failed` 只表示升级失败（`percent` 为失败时进度）；失败原因不在该事件中携带，旧版本继续运行，平台可结合 `ota.query` 与设备日志排查。

### 5.8 断线期间的数据

| 数据 | 断线时 | 重连后 |
|---|---|---|
| `status.report` | 不发 | 立即补一条 retained 状态 |
| 事件 | 写入缓存（512 条，满了覆盖最旧） | 按 16 条/页补报 |
| 遥测 | **每次传感器上报**记录一条（最多 256 条，覆盖最旧） | 逐条补报，保留原始 `ts` |
| 实时遥测周期 | — | 恢复为与心跳同周期 |

> 事件与遥测缓存都在内存中，**网关重启会丢失尚未补报的内容**。

## 6. 数据口径汇总

| 项 | 规则 |
|---|---|
| 水位单位 | 上行 JSON 用 cm（一位小数）；内部按 mm 计算 |
| 告警/档位 | 取在线且 enabled 传感器的**最高值** |
| 有效水位 `effective.levelCm` | 取在线且 enabled 传感器的**平均值** |
| 在线判据 | 超过 `3 × reportPeriodSeconds` 未收到该传感器上报即判离线 |
| `{level}` 占位符 | 当前水位整数 cm（截断）；0~9 补一个尾随空格 |
| 遥测周期 | 跟随心跳 `statusIntervalSeconds`，首条立即，失败 5s 后重试 |
| 联动防重发 | 档位未变化不重复下发；下发失败保留待重试 |
| 手动模式 | `dev.ctrl` 或 `rule.mode=manual` 后生效；超时或平台切回 `auto` 后回归 |

## 7. 绑定 / 解绑流程

```
平台 → sen.bind {pairWindowSeconds:60}    → 应答 code 0（仅窗口打开）
现场给设备上电/按配对键
设备 → 网关（LoRa 配对）→ 网关回确认
网关 → event.device {event:"bound", uid:"21...", devType:"sensor"}
平台保存 uid → sen.set 设置名称/参数
```

- 一个窗口只能绑一台；绑 N 台开 N 次窗口。
- 绑定成功后网关写入配置并分配默认值（见第 8 章），平台可随后 `sen.set` 修改。
- 解绑：`sen.unbind` → `code 0` 受理 → `event.device(unbound / unbind_failed)` 异步结果。

## 8. 配置域与默认值

### 8.1 system

| 字段 | 取值 | 默认 | 生效 |
|---|---|---|---|
| `gwId` | 26 位 hex，首字节 `11` | 设备 ID | 重启 |
| `password` | ≤32 字节，空=不校验 | 空 | 立即 |
| `timezone` | -12~+14 | 8 | 立即（仅记录） |

### 8.2 network

| 字段 | 取值 | 默认 | 生效 |
|---|---|---|---|
| `host` / `port` | 域名或 IP / 1~65535 | 现场配置 / 1883 | 重启 |
| `tls` | 当前仅 `false` | false | 重启 |
| `clientId` | ≤32 字节 | 等于 `gwId` | 重启 |
| `username` / `password` | ≤32 / ≤64 字节 | 现场配置 | 重启 |
| `keepAliveSeconds` | 30~300 | 60 | 重启 |
| `reconnectMinSeconds` | ≥1 | 5 | 立即 |
| `reconnectMaxSeconds` | ≥min | 300 | 立即 |

## 9. 手动控制与联动

- 自动模式：水位状态迁移到 0~3 档后，按 `gears[].targets` 选择设备，渲染模板（`{level}`）并下发；档位未变不重复下发。
- 手动模式：`dev.ctrl` 直接指定档位与文本（文本原样，不套档位模板）；执行后进入 `manual`，超时或 `rule.mode auto` 回归。
- 传感器全部失联：按 `rules.sensorOfflinePolicy` 执行（keep/alarm/off），并产生事件。
- 部分失联：在线传感器继续参与，离线设备单独产生 `event.device(offline)`。

## 10. 固件升级（OTA）

网关采用 **A/B 双分区**：

- OTA 只写“非当前运行分区”；新固件启动后进入观察期，健康确认后转正；确认失败自动回退旧分区；
- 平台通过 `status.report.slot`（`A`/`B`）判断当前运行分区，**下发另一分区对应的镜像**：
  - 当前 `A` → 下发 B 版镜像；
  - 当前 `B` → 下发 A 版镜像。
- 内部构建约定：版本号末位**奇数→B 版**、**偶数→A 版**（平台以 `slot` 为准即可，不必依赖该规则）。

流程：

```
平台 → ota.start {version,url,size,md5} → 应答受理
网关 → ota.progress downloading
网关 → ota.progress verifying(100)      ← 下载完成
网关 → ota.progress installing(100)      ← 已写好、等待重启
网关重启 → status.report.fwVersion=新版本  ← 升级成功
```

- `ota.query` 无 `done`；以重启后的 `fwVersion` 判定成功。
- 失败经 `ota.progress {state:"failed", msg}` 上报，旧版本继续运行。
- `ota.abort` 仅下载阶段有效。

## 11. 错误码

| code | 含义 |
|---|---|
| 0 | 成功 |
| 1001 | 参数错误/缺失；`sen.set`/`dev.set` 携带只读字段 |
| 1002 | 配置版本冲突（`data.currentVersion` 返回当前版本） |
| 1003 | 目标设备不存在（未绑定/已停用） |
| 1004 | 目标设备离线 |
| 1005 | 子设备 LoRa 响应超时 |
| 1006 | 当前状态不允许（版本相同、升级在途、不可中止等） |
| 1007 | 网关内部/存储错误 |
| 1008 | 应用层密码校验失败 |
| 1009 | 子设备数量已达上限 |
| 1010 | 存储空间不足 |
| 1011 | 应答过大，请分域查询 |
| 2001 | OTA URL 非法 |

> 下载/校验失败不作为命令应答码返回，统一经 `ota.progress {state:"failed"}` 上报。

## 12. 与甲方协议文档的差异说明（重要）

以下为当前固件的实际行为，与 `gateway-protocol.md V0.3` / `gateway-config.md V0.3` 的差异点，平台对接以本手册为准：

1. **遥测 QoS**：当前固件以 **QoS 0** 发布 `telemetry`；协议文档写 QoS 1。平台按 QoS 1 订阅仍可收到，弱网下可能丢包。
2. **遥测周期**：与心跳严格同周期（`statusIntervalSeconds`），**不再因水位变化额外触发**；首条立即发送。
3. **有效水位**：`effective.levelCm` 为**平均值**；`status`/`gear` 按**最高值**判定（双口径，可能不一致）。
4. **绑定默认上报周期**：当前固件绑定后默认 **300s**（协议文档写 60s）；平台可随后 `sen.set` 修改。
5. **`dev.ctrl` 文本**：完全透传，**不自动补档位模板**；空串就是空。文本中的 `{level}` 仍会替换。
6. **`status.report` 新增 `slot` 字段**：用于 OTA 选包（A/B）。
7. **`ota.progress` 新增 `verifying(100)`**：明确表示“下载完成”；随后才是 `installing`。`failed` 事件不带 `msg` 字段。
8. **断线缓存**：事件 512 条、遥测 256 条，均在**内存**中，网关重启会丢失未补报数据（协议文档描述的“断电不丢”当前未实现）。
9. **TLS**：当前仅支持明文 MQTT（`tls=false`）。
10. **`measureMode=distance`**：字段保留，当前固件按传感器上报的液位值透传，不做距离换算。
11. **`serial`**：已废弃，不参与流程；`sen.set` 携带返回 1001，`dev.set` 携带 `serial`/`type` 返回 1001。
12. **`sys.time_sync`**：已废弃，平台不应再使用；网关时钟由 4G 模组自动授时。
13. **应答体积**：模组单条发布上限约 1024 字节，超过返回 `1011`；`cfg.query` 请分域。

## 13. 典型示例

### 13.1 修改告警阈值

```json
{ "cmd": "cfg.set", "msgId": "c100", "ts": 1735689600,
  "data": { "expectVersion": 6,
            "sections": { "thresholds": { "alarmCm": 12, "confirmCount": 2 } } } }
```

应答：

```json
{ "cmd": "cfg.set", "msgId": "c100", "code": 0, "msg": "ok", "ts": 1735689601,
  "data": { "configVersion": 7, "applied": ["thresholds"], "rejected": [] } }
```

```json
{ "cmd": "dev.ctrl", "msgId": "d01", "ts": 1735689600,
  "data": { "uid": "all", "gear": 3, "ledText1": "早上好" } }
```

设备侧只显示 `早上好`；`ledText2` 与 `ttsText` 为空，不会自动补模板。

```json
{ "cmd": "cfg.query", "msgId": "q01", "ts": 1735689600,
  "data": { "sections": ["thresholds", "gears"] } }
```
